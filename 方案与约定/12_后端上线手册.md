## 0. 「上线」的验收定义

不是"能跑起来"，而是同时满足：

| # | 门槛 | 判定方式 |
| --- | --- | --- |
| 1 | 公网 HTTPS 可访问，只暴露 `/api/relay/*` | 外部 curl 控制台路径返回 404 |
| 2 | 连续运行 7 天无人工干预 | `systemctl show -p NRestarts` 增长为 0 |
| 3 | 服务器重启后租户 bot 自动重新上线 | 重启 systemd 后日志出现 `[tenant:...] ... 启动成功`；单进程异常退出目前不自动重启（后续补） |
| 4 | 备份可恢复 | 做过一次完整恢复演练（§11） |
| 5 | 审核员能完整体验主链路 | 用「粘贴/分享」通道走通，不依赖 QQ 群 |

> **第 5 条最重要**：QQ 的资质限制决定了审核员大概率不会去建 bot。**产品对外承诺的主链路必须是粘贴/分享**，bot 是增强项。
>
> **2026-10-28 范围收缩**：`QQBOT_GROUP_COLLECT=0`，自动群采集关闭；bot 不接收/不落库群消息，只处理用户主动私聊/转发。上线验收不要以「群消息入库」为主链路。

## 1. 目标架构

```
                 ┌──────────── 公网 443 (Caddy, 自动 HTTPS) ────────────┐
                 │  只反代 127.0.0.1:8731（公开口，仅 /api/relay/*）      │
                 └───────────────────────────┬──────────────────────────┘
                                             ▼
┌──────────────────────── /opt/zhiliao/app （单目录部署） ────────────────────────┐
│  server.py  (systemd: zhiliao)                                                  │
│   ├── 控制台口 127.0.0.1:8730（Basic Auth，仅本机）                              │
│   ├── 公开口   127.0.0.1:8731（/api/relay/*；/dev/ingest 已屏蔽）               │
│   ├── 自营 bot：botpy_main.py 子进程（QQBOT_AUTOSTART_BOT=1，可选）             │
│   └── 租户 bot：每租户一个 botpy_main.py 子进程（tenant_manager 管理）          │
│                                                                                 │
│  数据文件（全部在 app 目录内，随代码一起备份）：                                  │
│   relay_store.json / group_names.json / group_lexicon.json / tenants.json      │
│   bot.db / botpy.log / .env.prod / service_account.json / .relay_key          │
└─────────────────────────────────────────────────────────────────────────────────┘
```

> **`bot.db` 历史数据**：自动群采集关闭后不会新增群消息，但旧库可能已有历史 `group_messages`（本机 375 条）。上线前如不需要运维回放，先清空该表；否则它不在 App 主链路里。

| 端口 | 绑定 | 用途 | 对外 |
| --- | --- | --- | --- |
| 443 | Caddy | HTTPS | ✅ |

| 8730 | 127.0.0.1 | 运维控制台 | ❌ |
| 11434 | 127.0.0.1 | Ollama（若启用） | ❌ |

## 2. 容量与机型（先算清，别买错）

### 2.1 每个进程的实测开销（2026-10-30 本机实测，Windows 空闲态）

| 进程 | Private | Working set | 说明 |
| --- | --- | --- | --- |
| `server.py`（无租户） | 53 MB | **72 MB** | HTTP + relay 空窗口 + LogBuffer |
| 单个租户 `botpy_main.py` | 43 MB | **63 MB** | botpy + aiohttp + httpx + aiosqlite，空闲态 |

> 说明：Windows 数值通常略高于 Linux（glibc 更省），上线后用 `ps -o rss` 复核一次。
> 本机沙箱里 `tenant_manager` 拉子进程被拒（`WinError 5`），所以第二行是**单独起一个 `botpy_main.py` 进程**测的，
> 与生产"每租户一个子进程"的形态等价；数值是**空闲态**，有消息时会略涨（缓冲，几十 MB 内）。

### 2.2 机型对照（**仅转发、无模型、无群采集**）

按 63 MB/租户 + 72 MB 主进程 + 30% 余量算：

| 机型 | 可用内存 | 20 租户实占 | 可托管（含余量） | 结论 |
| --- | --- | --- | --- | --- |
| 2C2G | ~1.8G | ~1.4G | 12–15（建议 ≤10） | 紧，不推荐 |
| **2C4G** | ~3.6G | **~1.4G** | **20–30** | ✅ **审核期够用**；`MAX_TENANTS=20` 时仍留约 2G |
| 4C8G | ~7G | ~1.4G | 50+ | 只有要跑 `qwen3:4b` 才需要 |

**结论**：
- **只剩转发时，2C4G 足够**——2 vCPU 对"转发 + 合并转发的正则聚类"不是瓶颈（单用户场景 CPU 峰值几十毫秒）；
- **要上 `qwen3:4b` 就必须 4C8G**（模型 2.5G + Ollama 0.5–1G，2C4G 会 OOM）；
- 2C2G 只差 ¥89/年，不值得为它冒 OOM 风险。

`QQBOT_MAX_TENANTS` 默认 20（代码里 clamp 到 1–200）——**先把它设为机型能承受的值**，别让它成为 OOM 的入口。

### 2.3 LLM 必须三选一（2C2G 跑不了 9B）

| 方案 | 配置 | 代价 |
| --- | --- | --- |
| **规则降级（推荐 v1）** | 不装 Ollama，`llm_parse.available()` 返回 false | 抽取质量下降，零成本零幻觉 |
| 外部 API | 改 `llm_parse` 的 `OLLAMA_BASE`/模型为兼容端点 | 正文出服务器，**隐私政策必须写** |
| 独立 GPU 机 | 另开一台跑 Ollama，`OLLAMA_BASE` 指过去 | 成本高 |

**上线默认：规则降级。** 审核与答辩演示再临时开模型。

## 3. ⚠️ 上线前必须先修的 6 件事（基于当前代码）

这几条不是"优化"，是**公网暴露后的安全问题**，按优先级：

| # | 问题 | 证据 | 后果 | 修法 |
| --- | --- | --- | --- | --- |
| **P0** | `/api/relay/tenant/register` 可被滥用 → **子进程风暴** | `tenant_manager.start()` 每次 `create_subprocess_exec` 起 botpy，并 `wait_ready(10s)` | 攻击者批量注册设备 + 提交无效凭据 → 大量子进程/10s 占用，等同轻量 DoS | ① 同 device 并发锁（跨请求）；② 全局 pending 上限；③ 失败立即 kill + 冷却；④ 按设备/IP 限流 |
| **P0** | `/api/relay/device/register` 无上限，且每次全量重写 `relay_store.json` | `relay.register_device()` | 磁盘写放大 + 无限增长 | IP 限速（如 1 次/分钟）+ 单 IP 设备上限 + 过期回收 |
| **P0** | 控制台未设密码 = **不鉴权** | `_console_authorized()`：`if not CONSOLE_PASSWORD: return True` | 若误绑 0.0.0.0 即完全裸奔 | 必须设 `QQBOT_CONSOLE_PASSWORD`，且 `QQBOT_CONSOLE_HOST=127.0.0.1` |
| **P1** | `/api/relay/admin/*` 在公开口可达（靠 `x-relay-key`） | 路由表含 admin | 密钥泄露即管理面沦陷 | 公开口直接 404 掉 `/admin/*` + 轮换 key |
| **P1** | 租户私聊未校验发送者是否为 Bot 主人 | `botpy_main._handle_tenant_c2c` 按 `TENANT_DEVICE_ID` 直投 | 任何人给该 Bot 发消息都会进入 owner 的「待确认」 | 绑定后要求用户发一次一次性校验码；或记录首个 `user_openid` 做白名单 |
| **P1** | `botpy.log` 只追加、无轮转 | `LogBuffer.add()` 直接 append | 磁盘写满 → 服务挂 | 上 `logrotate`（模板已给） |

> **2026-11-01 已修**：
> - `/device/register`、`/tenant/register`、`/parse`、`/bind/code` 已按 IP 限流（默认 10/5/20/10 次每分钟，超限 `429 rate_limited`），`/forward/pending` 轮询不限流；
> - 租户启动增加并发上限（默认 2）与排队上限（默认 8），满了返回 `tenant_busy`，避免子进程风暴；
> - 公开口 `/api/relay/admin/*` 直接 404；
> - `.env.prod`、`service_account.json`、`relay_store.json`、`bot.db`、`botpy.log`、`tenants.json` 均 600；`tenants.json` 与 `relay_store.json` 每次写入后强制 600；
> - `logrotate`、每日备份 cron、每 2 分钟探活 cron 已装。
>
> **仍待补**：租户私聊的 **owner 校验**（任何人给 Bot 发消息仍会进 owner 的待确认队列）。

> 另外两条**纪律**：生产 `.env` 里 `QQBOT_DEV_INGEST` 必须是 `0`；`.relay_key`、`tenants.json`、`.env.prod` 权限必须 `600`。

## 4. 服务器初始化（Ubuntu 24.04）

```bash
# 1) 基础包
sudo apt update && sudo apt install -y python3 python3-venv python3-pip caddy rsync curl ufw

# 2) 建专用用户（不用 root 跑服务）
sudo useradd -m -s /bin/bash zhiliao
sudo mkdir -p /opt/zhiliao/app /opt/zhiliao/backups /opt/zhiliao/snapshots
sudo chown -R zhiliao:zhiliao /opt/zhiliao

# 3) 拉代码（示例：从本机 scp 或私有仓库）
#    本机执行：
#    scp -r qqbot-backend/* zhiliao@<ip>:/opt/zhiliao/app/   （排除 .venv）
sudo -iu zhiliao
cd /opt/zhiliao/app
python3 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt
```

> Python 版本：云镜像多为 **3.12**，本地是 3.14。装完先跑一次
> `.venv/bin/python -X utf8 -m py_compile server.py relay.py botpy_main.py tenant_manager.py`
> 确认语法兼容。

## 6. 配置文件（`/opt/zhiliao/app/.env.prod`）

模板见 `deploy/env.prod.example`。**主密钥是新增的关键项**：

```bash
# 生成 32 字节主密钥（base64），只做一次，之后固定不变
openssl rand -base64 32
```

> ⚠️ **`QQBOT_SECRET_KEY` 丢失 = 所有租户 bot 凭据无法解密**（用户必须重新绑定）；**泄露 = 全部凭据可解**。
> 它必须和 `tenants.json` **配套备份**，但**不要**放在同一个文件里（备份包加密后再存异地）。

关键项速查：

| 变量 | 生产值 | 说明 |
| --- | --- | --- |
| `QQBOT_CONSOLE_HOST` | `127.0.0.1` | 控制台绝不出公网 |
| `QQBOT_CONSOLE_PASSWORD` | 强口令 | 不设=不鉴权 |
| `QQBOT_PUBLIC_HOST` | `127.0.0.1` | 由 Caddy 反代 |
| `QQBOT_DEV_INGEST` | `0` | 生产必须关 |
| `QQBOT_AUTOSTART_BOT` | `0` 或 `1` | 是否启自营 bot |
| `QQBOT_RELAY_KEY` | 新随机值 | 不沿用本机 `.relay_key` |
| `QQBOT_SECRET_KEY` | base64(32B) | 租户凭据加密主密钥 |
| `QQBOT_MAX_TENANTS` | 按机型 | 见 §2.2 |
| `QQBOT_GROUP_COLLECT` | `0` | 自动群采集开关；默认 0（不接收/不落库群消息） |
| `QQBOT_PUSH_SA` | 路径 | Push Kit 服务账号 |

## 7. systemd（含"子进程会一起被杀"的注意点）

模板：`deploy/zhiliao.service`

```ini
[Service]
Type=simple
User=zhiliao
WorkingDirectory=/opt/zhiliao/app
EnvironmentFile=/opt/zhiliao/app/.env.prod
ExecStart=/opt/zhiliao/app/.venv/bin/python -X utf8 server.py
Restart=always
RestartSec=5
TimeoutStartSec=120
TimeoutStopSec=40
KillMode=control-group
```

**为什么是这几个值**：

- `ExecStart` 必须用 **venv 的 python**：租户子进程用的是 `sys.executable`（见 `tenant_manager.start()`），用系统 python 会缺依赖；
- `KillMode=control-group`（默认）：重启时把**所有 botpy 子进程**一起收掉，避免孤儿；
- `TimeoutStartSec=120`：启动时 `TENANT_MANAGER.start_all()` 会逐个拉起租户 bot，每个 `wait_ready` 最多 10s；
- `TimeoutStopSec=40`：给 `shutdown_all()` 留时间优雅停子进程。

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zhiliao
systemctl status zhiliao --no-pager
journalctl -u zhiliao -n 100 --no-pager
```

## 8. HTTPS（Caddy，自动证书）

模板：`deploy/Caddyfile`

```caddyfile
api.example.com {
    encode gzip
    request_body { max_size 4MB }
    reverse_proxy 127.0.0.1:8731
    header {
        Strict-Transport-Security "max-age=31536000"
        X-Content-Type-Options nosniff
        -Server
    }
}
```

**DNS**：`api.example.com` A 记录指向服务器公网 IP（境内服务器需**先完成 ICP 备案**，否则 80/443 会被拦）。

```bash
sudo systemctl reload caddy
curl -I https://api.example.com/api/relay/health
```

**验证隔离**（必须两条都过）：

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://api.example.com/api/status       # 期望 404
```

## 13. 发布流程（含自动回滚）

```bash
# 本机：打包（排除 .venv 与密钥）
tar czf release-$(date +%Y%m%d-%H%M).tar.gz -C qqbot-backend . \
  --exclude='.venv' --exclude='.env*' --exclude='tenants.json' --exclude='*.log'

# 服务器：部署（脚本内部会先打快照，健康检查失败自动回滚）
scp release-*.tar.gz zhiliao@<ip>:/tmp/
ssh zhiliao@<ip> 'bash /opt/zhiliao/app/deploy/deploy.sh /tmp/release-*.tar.gz'
```

`deploy.sh` 的步骤：**快照 → 解包覆盖（保留密钥与数据）→ 装依赖 → 重启 → 30s 健康检查 → 失败自动恢复快照并重启**。

**发布窗口**：避开课间/晚间消息高峰；发布前先在测试机跑 §4.3 的回归测试。

## 14. 审核期专项

| 项 | 做法 |
| --- | --- |
| 服务保活 | 审核前一周开监控，确认 `NRestarts=0` |
| 审核员路径 | 审核说明写明：**用「粘贴/分享」即可完整体验**；BYOB 建 Bot 是增强项，可选；不要要求审核员必须建 Bot |
| 凭据边界 | 隐私政策/审核说明写清：用户 Bot 的 AppSecret 由服务端 AES-GCM 加密托管、不回传、仅用于连接；`DELETE /my/data` 可删除 |
| 群采集关闭 | `QQBOT_GROUP_COLLECT=0`；审核说明写清「不自动采集群消息，只处理用户主动转发」，避免审核员按群采集验收 |
| 关闭联调入口 | `QQBOT_DEV_INGEST=0`；外部访问 `/api/relay/dev/ingest` 应 404 |
| 控制台 | 不上公网；需要时用 `ssh -L 8730:127.0.0.1:8730` 隧道 |
| 演示数据 | 准备一个演示账号 + 3 条真实感消息，避免审核员看到空列表 |

## 16. 故障预案

| 故障 | 症状 | 处置 |
| --- | --- | --- |
| 磁盘满 | 日志写入失败、服务假死 | `logrotate` 立即转；`df -h`；清理 snapshots |
| 内存 OOM | 子进程被杀、`NRestarts` 增长 | 降 `QQBOT_MAX_TENANTS`；升机型；查租户内存泄漏 |
| 租户 bot 风暴 | 大量 `[tenant:...] 已启动` | 临时 `systemctl stop`，清理 `tenants.json` 异常项，补限流后再开 |
| QQ 封禁 | 日志 401/403、消息不发 | 平台封禁**不支持解封**；切备用 bot；通知用户走粘贴通道 |
| Ollama 挂 | 解析变慢/降级 | 规则降级自动生效；`systemctl status ollama` |
| 证书失效 | App 报网络错误 | `caddy` 日志；DNS 是否指对；手动 `caddy reload` |
| 主密钥丢失 | `tenant_secret_broken` | 只能让用户重新绑定（提前离线备份可避免） |
| 误删 `tenants.json` | 所有租户掉线 | 从备份恢复 + 重启（主密钥需一致） |
| 重装后 `bot_already_bound` | 新 device_id 提交同一 AppID，但 Secret 与旧租户不一致 | 同 Secret 会自动转移；重置过 Secret 的需先清旧租户/绑定或让用户重新创建 Bot |
