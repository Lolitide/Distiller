## 0. 先把三个「任务」分清楚（混了就全错）

| | 本机 `Task`（手机） | 云端 `BotTask` | 我们的后端（本仓库） |
| :-- | :-- | :-- | :-- |
| 落地 | `relationalStore`（§9.2 表，18 列） | AGC 云数据库（§6.3，**十字段**） | **只在内存 30 分钟窗口**，不落盘 |
| 谁写 | `repository/`（袁正锟） | `service/cloud/` 回写 | bot 进程推入（`relay.py`） |
| 对齐键 | `id` 自增；跨端靠 `client_task_id` | `client_task_id` | `msg_id`（消息）/ `candidate_id`（簇） |
| 原文 | `raw_text` / `raw_json` **存本机** | **不存**（只作云函数入参） | 内存窗口，30 分钟后连附件一起找不回 |
| 图片/文件 | 存（用户主动添加的） | **不存** | `/attachment` 过路：内存短缓存、不落盘 |

> 前端的设计口径是「**进得来的是文字，上得云的是字段**」（§6.4）。
> **我们的后端在 §6.2 的链路里就是那个「bot 进程 + 解析」**：QQ →（WebSocket 长连接）→ bot → 解析 → 下游。

## 2. 要拍板的第一件事：手机从哪儿拿「待办」

前端 §6.2 写了两条链路，并推荐**路径 B**（不依赖公网入口）：

```
路径 B（推荐）
  QQ 群消息 → QQ 平台 → WebSocket 长连接 ← bot 进程 ← 调 AGC 云函数 → 云数据库 → 手机拉取
手机侧（两条路径相同）
  冷启动 / 下拉刷新 → cloudDatabase 查「未同步」 → 本机待确认列表 → 用户确认
  → 写本机 relationalStore → 回写云端标记已同步或直接删除该条
```

**我们的后端可以有两种接法**，二选一（建议 A，改动最小、且与现有代码一致）：

| | 接法 A：手机直连我们的后端 | 接法 B：我们只做「bot + 解析」，字段进云 |
| :-- | :-- | :-- |
| 谁拉数据 | `service/cloud/` 改调 `/api/relay/*`（把"云"换成我们的后端） | 我们解析完 → 调 AGC 云函数写 `BotTask` → 手机仍从云数据库拉 |
| 需要做的 | 前端 `service/cloud` 写 HTTP 调用；后端已就绪（`05` 全部接口） | 后端加一个「写云函数」的出口；前端不用改拉取路径 |
| 数据边界 | 与我们一致（内存窗口，比云 TTL 7 天更严） | 原文仍不落云；但字段落到 AGC |
| 适配成本 | 低（后端零改动） | 中（要接 AGC、配云函数） |

> **本文档以下内容按「接法 A」写**（手机直连我们的后端）。选接法 B 的话，§3 的字段映射仍然适用，只是搬运工从 `service/cloud` 换成云函数。

## 3. 字段映射：候选 → 本机 `Task`

**数据源用 `GET /candidates`（不是 `/messages`）**：候选是**簇级**的（一个事项一条），自带稳定幂等键
`candidate_id` 与游标 `rev_seq`，正好对应前端的 `client_task_id` 与"增量拉取"。

| 本机 `Task` 表列（§9.2） | `model/Models.ets` 字段 | 我们的候选字段 | 处理 |
| :-- | :-- | :-- | :-- |
| `title` | `title` | `title` | 直接用（后端保证是原文子串） |
| `detail` | `detail` | `summary` | 直接用；`items`/`steps` 非空时可拼进 `detail` |
| `due_at` | `dueAt` | **`due_at`**（毫秒） | **直接用**；缺省才回退 `time_normalized` 本机换算 |
| `due_text` | —（Model 里没有） | **`due_text`** | **已补齐**：等于 `time_text`，不用再塞 `detail` |
| `location` | —（Model 里没有） | `place` | **已补齐**：候选本来就产 `place`，直接落 |
| `repeat` | `repeat` / `repeatText` | **`repeat` / `repeat_text`** | **已补齐**（规则从原文认「每天/每周/每月…」） |
| `priority` | `priority` | `priority` | **要映射**（见下） |
| `level`（难易） | `level` | **`level`** | **新增**：0 易 / 1 中 / 2 难，只参与排序 |
| `confidence` | —（repository 附加） | **`certainty`** | **已补齐**：后端直接给 0~100 整数 |
| `missing_fields` | —（repository 附加） | **`missing_fields`** | **已补齐**：后端给 `place`/`who`/`dueAt` 里缺的 |
| `category` | `category` | `category` | 预设 作业/考试/活动/通知/其他；可自定义 |
| `status` | `status` | — | 从邮箱/后端进来的**一律 `PENDING_CONFIRM(0)`** |
| `source` | `source` | **`channel`** | **已补齐**：`bot` / `manual`（另有 paste/share/voice 预留） |
| `raw_text` | —（repository 附加） | `source.msg_ids` → `GET /messages` 取 `content` 拼起来 | 「原文对照」靠它，**必须在确认页落库前拿到** |
| `raw_json` | —（repository 附加） | 整条候选 JSON | 第 3 周调参靠它，原样存 |
| `alarm` | `alarm` | — | **纯本机**（用户意图）：有 `due_at` 才给开关 |
| `remind_at` / `reminder_id` | `remindAt` / `reminderId` | — | **纯本机**（按设置页「提醒提前量」从 `due_at` 算） |
| `client_task_id` | —（落库时给） | `candidate_id` | **建议直接用** `candidate_id`（同簇稳定、天然幂等） |
| —（不上本机） | — | `kind` | `kind` **不进 Task**（已确认的裁定）；只用于「忽略」判定与筛选 |
| —（不上本机） | — | **`steps[]`** | 形态是 **`[{content, done}]`**（原为 `string[]`），直接落 `TaskStep[]` |
| —（不上本机） | — | `tags[]` | `tags: string[]` |

**`priority` 映射（4 档字符串 → 3 档数字）**：

| 候选 `priority` | 本机 `TaskPriority` |
| :-- | :-- |
| `urgent` | `URGENT = 2` |
| `high` | `IMPORTANT = 1` |
| `normal` | `NORMAL = 0` |
| `later` | `NORMAL = 0`（`later` 只表示"不急"，前端没有第 4 档） |

> `TaskStatus.EXPIRED(4)` **只有系统能写**（§9.3）；后端不给这个值。

## 4. 接口 ↔ 前端落位（按 §7.3 文件归属）

| 我们的接口 | 前端落位（谁） | 说明 |
| :-- | :-- | :-- |
| `GET /health` | `service/cloud/`（袁正锟） | 冷启动探测 `capabilities`；`ocr` 决定截图能否直传后端 |
| `POST /parse` | `service/ai` + 确认页（谢忠宇） | 手动添加：粘贴 / 分享 / 语音转写后的文字 / 截图 / 文件 → 预填确认页（**无状态、不落库**） |
| `GET /candidates` | `service/cloud/` → `repository/`（袁正锟） | **待办主数据源**：`after=cursor` 增量拉，按 `candidate_id` upsert；落到本机时 `status=PENDING_CONFIRM` |
| `GET /messages` | `service/cloud/` → `repository/` | 按候选 `source.msg_ids` 取「原话」写 `raw_text`；也是「查看原话」的兜底 |
| `GET /attachment` | `service/cloud/` | 图片/文件消息的**原始字节**（QQ 直链端上不可靠，走这里）；`index` 见候选/消息的 `attachments[]` |
| `POST /feedback` | `service/cloud/`（袁正锟） | 确认页「转成待办」= `accept`、「忽略」= `dismiss`；只记计数 |
| `GET /groups`、`/subscribe`、`/unsubscribe` | 设置页 / 群订阅（杜俊廷 + 袁正锟） | 用户挑要收哪些群 |
| `GET/DELETE /my/data` | 设置页 | 一键删服务端数据（绑定/订阅/配对码 + 该群词表） |
| `POST /messages/update` | **对接交付前端时用不到** | 它适用于「把 `/messages` 的 `parse` 直接当待办」的用法。交付前端改的是**本机 `Task`**（`repository`），不需要回改后端；是否保留这个接口由组长定 |

**三条调用硬规矩（§9.4，别破）**：
1. AI 能力只在 `service/ai/` 里**动态 import**（模拟器上静态 import 会闪退）；
2. 页面 → ViewModel → service → repository，**不跳层**；页面不直接调系统能力；
3. 权限申请集中在 `service/system/`，页面只拿结论。

## 5. 主流程：群消息 → 候选 → 确认页 → 本机 Task

```
QQ 群消息 ──WebSocket──▶ bot 进程（本仓库 qqbot_backend）
                           ├─ relay 内存窗口（30 分钟，原文不落盘）
                           └─ 候选管道：去重 → 聚类 → 模型/规则 → 安全闸（原文子串校验）
                                  ▼
手机「冷启动 / 下拉刷新」 ──▶ service/cloud 拉 GET /candidates?after=cursor
                                  ▼
                            repository 落库（status = PENDING_CONFIRM）
                                  ▼
                        待确认列表（A_TaskList）→ 用户进确认页
                                  ├─ 用户改字段（改的是本机副本）
                                  ├─ 点「确认」→ status = CONFIRMED，写 raw_text/raw_json
                                  │            → POST /feedback { action: "accept" }
                                  └─ 点「忽略」→ 本机标记 → POST /feedback { action: "dismiss" }
                                  ▼
                        本机 relationalStore（唯一真相）→ ReminderService 发布提醒
```

**几个必须写死的点**：
- **原文要在「确认」这一刻取到**（`raw_text` 永久保留、用于原文对照）；候选过期后 `/messages` 也取不到了——所以确认页要么当场取，要么接受 `raw_text` 为空。
- **幂等**：同一 `candidate_id`/`client_task_id` 重复落库按同一条处理（前端 §6.3 的规矩，后端 `rev_seq` 也是这个语义）。
- **`due_at` 的时区**：后端 `time_normalized` 是**本地时间字符串**（`YYYY-MM-DD HH:mm`），前端转毫秒时间戳时别再按 UTC 解析。

## 8. API 速查（App 侧会用到的全部）

| 接口 | 方法 | 鉴权 | 一句话 |
| :-- | :-- | :-- | :-- |
| `/api/relay/health` | GET | 设备身份 | 能力协商：`api_version` / `capabilities`（含 `ocr` 时截图可直传） |
| `/api/relay/device/register` | POST | — | 注册设备拿 `device_id` / `token` |
| `/api/relay/bind/code` | POST | 设备身份 | 生成配对码（控制台网页授权） |
| `/api/relay/bind/status` | GET | 设备身份 | 轮询绑定状态 |
| `/api/relay/groups` | GET | 设备身份 | 可订阅群列表 |
| `/api/relay/subscribe` / `unsubscribe` | POST | 设备身份 | 订阅 / 退订 |
| `/api/relay/messages?after=&limit=` | GET | 设备身份 | 消息 + `parse`（取「原话」写 `raw_text` 也用它） |
| `/api/relay/candidates?after=&limit=` | GET | 设备身份 | **待办主数据源**：`rev_seq` 游标 + 按 `candidate_id` upsert |
| `/api/relay/parse` | POST | 设备身份 | 无状态抽取（文本 / 截图 / 文件）；501 = 端侧兜底 |
| `/api/relay/feedback` | POST | 设备身份 | accept / dismiss 回传 |
| `/api/relay/attachment?msg_id=&index=` | GET | 设备身份 | 附件原始字节过路（不落盘） |
| `/api/relay/my/data` | GET / DELETE | 设备身份 | 隐私：一键删除 |

- 请求头：`X-Device-Id` + `X-Device-Token`（`register` 拿到后全程携带）。
- 错误码：`401`（身份失效 → 重新 register）/ `400` / `404` / `500` / **`501 not_supported`（功能在但依赖不在，前端降级，不是报错）**。
