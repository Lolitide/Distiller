# 10 · 主体资质与法律风险（BYOB / QQ 机器人公开使用 / 个体户）

> 写作日期：**2026-10-28**
> 触发问题：要让 QQ 机器人「被公开搜索并添加好友」，管理员账号至少要是个体户；三个人是否必须成立个体户？有没有法律风险？
>
> **2026-10-28 方向变更**：已放弃「我们运营一个公开 Bot」的路线，改为 **BYOB**——用户在 App 里创建自己的 QQ Bot，填入 AppID/AppSecret，后端加密托管并拉起该 Bot。下面 §0–§2 的平台规则仍然有效，但**「必须注册个体户」的前提已不成立**；新的责任重点变成**用户凭据托管 + 转发他人消息**（见 §4）。
>
> ⚠️ **免责声明**：我不是律师，本文是**平台规则 + 公开法规的整理**，不构成法律意见。涉及个人信息处理、合伙协议、税务登记的部分，**建议花 1 小时找执业律师或学校法务确认**（成本远低于出事）。

---

## 0. 结论（先看这五条）

1. **平台规则没有变**：个人主体的 Bot **不能公开被搜索/被任意用户添加**，只能进「自己是群主/管理员」的群；私聊只能加「开发体验用户号码」。
2. **但你们现在不需要跨过这个限制**：BYOB 让**每个用户自己创建 Bot**，该 Bot 天然属于该用户；我们只负责托管连接。**不需要为了公开 Bot 去注册个体户。**
3. **BYOB 的代价**：每个用户要走一次「创建 Bot → 填 AppID/AppSecret」；Bot 只能覆盖该用户自己管理的群，**不能自动读别人的群**。当前产品承诺只做「私聊/转发 → 待确认」。
4. **新的最大风险是凭据托管与个人信息**：`tenants.json` 里是用户的 Bot Secret（AES-256-GCM 密文），一旦泄露可被用来冒充该 Bot；同时仍在转发**群里其他人的消息**，那些人没有同意过（§6）。
5. **建议**：**先走 BYOB，不注册个体户**；把「手动粘贴/分享」作为主链路，Bot 作为增强项。只有将来确实需要「一个公开 Bot 覆盖大量别人的群」时，再走个体户（§5）。**个人主体不能升级，所以不要现在为了“以后可能”去注册。**

## 1. 平台规则（已核实，有原文）

### 1.1 卡点不是"能不能创建机器人"，而是"公开使用"

QQ 机器人官方 FAQ《[QQ Bot 常见问题答疑](https://bot.q.qq.com/wiki/bot_FAQ/)》原文：

> **Q：机器人如何公开添加进群、频道**
> 目前在最新机器人管理端中，**企业主体公开使用已开放，个人主体暂不支持公开使用**。
> 个人主体的机器人如需添加群聊，**机器人创建者可直接添加自己是群主/管理员身份的群聊**（升级最新版移动QQ添加）。
> 个人主体的机器人如需添加人员私聊使用，可以在新版管理端「开发设置」中添加**开发体验用户号码**。

**逐句翻译成"你们能做什么"**：

| 能力 | 个人主体 | 企业/个体户主体 |
| --- | --- | --- |
| 在群里用机器人 | ✅ **仅限你是群主/管理员的群** | ✅ 公开可加 |
| 别人能搜到/加好友 | ❌ | ✅（需开「公开服务」） |
| 任意用户私聊机器人 | ❌ 只能加「开发体验用户号码」 | ✅ |
| 机器人数量 | 5 个 | 10 个（同主体共用 50） |

### 1.2 "个体户"为什么算企业主体

QQ 开放平台《[平台入驻文档](https://q.qq.com/wiki/)》把注册主体分三类：**企业、个体户、个人**。其中「企业/个体户」共用一套材料（**营业执照** + 法人/经营者人脸识别或对公打款），「个人」用身份证 + 人脸。

FAQ 里"个人认证怎么升级企主体"的答复更直接：

> 个人主体无法直接升级为企业主体，可以**使用新的邮箱账号重新注册并认证企业主体（个体户）**，可绑定相同的管理员 QQ。

→ 所以在 QQ 平台的语境里，**个体户 = 够用的"企业主体"**。这是"个体户"这个说法的来源。

### 1.3 ⚠️ 最贵的坑：不可逆

| 事实 | 后果 |
| --- | --- |
| **个人主体不能升级**为企业/个体户 | 将来想公开，必须**新邮箱重注册** + **新建机器人**（AppID/AppSecret 全变） |
| 机器人 AppID 变了 | 后端 `.env` 要改、群里要重新添加、用户要重新绑定 |
| 平台**暂不支持注销**开放平台账号与主体 | 注册了就撤不回，长期背着 |
| 公开服务打不开的常见原因 | 新账号审核中（约 3 天）、账号/管理员异常、**未完成 QQ 钱包实名认证** |

**结论**：**别抱着"先用个人主体做着，以后再说"的心态**。如果确定要做成「可公开添加」的产品，**就在建机器人之前**把主体定下来。
>
> **但当前走 BYOB，不需要公开 Bot**，所以这条不是本期的阻碍；只有未来确实要做「一个公开 Bot 覆盖别人的群」时才适用。

## 2. 你们的三条路（含成本与适用性）

| | **A. 零主体：只做群内** | **B. 个体户** | **C. 有限责任公司** |
| --- | --- | --- | --- |
| 能公开搜索/加好友 | ❌ | ✅ | ✅ |
| 能任意用户私聊 | ❌（仅体验用户） | ✅ | ✅ |
| 注册成本 | 0 | 低（营业执照免费/代办几百元） | 中（核名、章程、银行户） |
| 持续成本 | 0 | 记账报税约 2k–4k/年（或自己零申报）+ 时间 | 更高（记账、年报、审计视规模） |
| 责任范围 | 个人（本来就有） | **无限责任**（民法典 56） | **以认缴出资为限** |
| 税务 | 无（个人劳务另算） | 必须登记、按期申报（含零申报） | 同左 + 企业所得税 |
| 年报 | 无 | **每年 1/1–6/30 必报** | 同左 |
| 注销 | — | 需清税，可简易注销 | 更麻烦 |
| 适合 | 课程项目、校内小范围、群主可控 | 要做成公开产品、但不想开公司 | 明确要商业化/融资 |

> **现在实际走的是 BYOB（不是上表 A/B/C）**：我们不运营公开 Bot，而是让用户创建自己的 Bot；因此上表的「能公开搜索/加好友」不再是我们需要的能力。BYOB 的适用性、成本和责任见 §4。

**D. 挂靠学校/社团**：理论上可用事业单位/社团法人作主体，但**实际上拿不到**（需要公章、法人证书、学校审批），且责任主体不清——**不建议**。

## 3. 个体户的法律风险（逐条，含依据）

### 3.1 无限责任 —— 这是最大的一条

《民法典》**第五十六条**：

> 个体工商户的债务，个人经营的，以个人财产承担；家庭经营的，以家庭财产承担；无法区分的，以家庭财产承担。

含义：**个体户不是"有限责任"**。如果因为 app/机器人出了事（隐私泄露、侵权、用户索赔、平台罚款），**经营者要用个人财产承担**。
对比：有限责任公司以认缴出资为限（但仍可能因人格混同、抽逃出资被追责）。

### 3.2 税务：不是"注册完就没事"

- 个体户需办**税务登记**（现在多与营业执照"多证合一"合并），并**按期申报**；
- **没有收入也要"零申报"**；不申报 → 可能被列为**非正常户**、罚款，且影响经营者个人信用；
- 若有收入：增值税（小规模纳税人按季）、个人所得税（经营所得）等；
- 2026 年起对个体户"非正常户"的清理趋严（有报道称 2026-11-01 起全国统一执法、拖延罚款更高）——**别把"没收入所以不用管"当真理**。

### 3.3 工商年报：每年 1/1–6/30，漏报有罚

依据《市场主体登记管理条例》**第七十条**与《企业信息公示暂行条例》：

- 未按时年报 → **列入经营异常名录**，可处 **1 万元以下罚款**；
- 连续 2 年未报且**登记住所/经营场所无法联系** → 可**吊销营业执照**；
- 失信信息通过国家企业信用信息公示系统公示，**联合惩戒**（信贷、招投标、荣誉等）。

> 另注意：年报要**如实**填，不要为了省事全填 0（"零值年报"本身可能被认定信息不实）。

### 3.4 经营场所：学生最实际的障碍

个体户登记需要**经营场所**。学生没有商铺，通常两条路：

- **住宅"住改商"**：需利害关系业主同意/居委会证明，**各地执行差异大**；
- **集群注册/托管地址**：部分地区允许"一址多照"或托管，**西安各区是否支持需问当地市场监管所**。

→ 这一条**建议先去街道/市场监管所问清楚**，否则可能卡在注册环节。

### 3.5 学生身份：一般可以，但有两个点要自己确认

- **学籍**：法律未禁止在校学生登记个体户，一般不影响学籍；
- **考公/选调/事业单位**：部分岗位要求申报"经商办企业"情况，个别岗位有限制 → **如果你有这个规划，先查目标岗位的公告**。

（这两条属"需自行确认"，我无法替你判断。）

### 3.6 个人信息处理者责任（PIPL）—— 比个体户本身更该担心

见 §6 专章。简单说：一旦以个体户名义运营，你就是**个人信息处理者**，要承担告知同意、最小必要、安全保障、泄露通知等义务。

### 3.7 内容与平台责任

- 群消息可能含违法/侵权内容，机器人转发 → **运营主体要担责**；
- QQ 平台明确：**机器人封禁不支持解封**（FAQ 原文），违规使用会导致机器人或账号封禁；
- AI 能力"由开发者自主选配"，输出违规同样封禁。

### 3.8 三个人的内部风险（最容易被忽略）

如果只登记**一个人**为经营者：

- 另外两人在法律上**没有任何股权/权益**；
- 出了钱、写了代码，**无法主张所有权**；
- 债务虽由经营者对外承担，但**内部追偿**没有依据（除非有协议）；
- 将来退出、分钱、卖项目，全靠"感情"。

→ **必须签书面协议**（要点见 §5.1）。

### 3.9 主体不一致的风险

可能出现：**App 开发者/备案主体 = 个人**，**QQ 机器人主体 = 个体户**。

- 法律上不必然违法，但**隐私政策里的"个人信息处理者"必须写清楚**；
- 若两边都处理数据，要么统一主体，要么签**委托处理协议**并披露；
- 华为审核也可能问"你们到底是谁在提供服务"。

→ **建议：一旦注册个体户，尽量让 App 开发者、备案、机器人三处主体一致**（华为开发者主体变更是另一道流程，需单独确认）。

## 4. 如果走 BYOB（当前路线）：要改什么

BYOB 的含义：**用户在 App 里创建自己的 QQ Bot，把 AppID/AppSecret 填进来；后端按设备加密保存并拉起该 Bot 的连接。** 我们不再运行一个「嗅嗅」公开 Bot，也不再用配对码。

### 4.1 已经落地的机制

1. App「设置 → 绑定 QQ」：复制创建链接到 QQ 内打开 → 输入 AppID/AppSecret → 绑定。
2. 后端 `POST /api/relay/tenant/register`：按设备保存 `AppID` + **AES-256-GCM 密文 AppSecret**（主密钥 `QQBOT_SECRET_KEY`），并启动一个 `botpy_main.py` 子进程。
3. 用户在该 Bot 的私聊里发消息 → 后端按 `device_id` 直投**内存转发队列**（30 分钟 TTL）→ App 取走并进入「待确认」。
4. 解绑 / `DELETE /my/data`：停止子进程、删除租户记录与绑定；`tenants.json` 里的密文一并删除。

### 4.2 责任变化

- **不再需要个体户**：Bot 是用户自己的，个人主体即可创建和使用。
- **不采集群消息**：`QQBOT_GROUP_COLLECT=0`，Bot 的群消息回调直接忽略，不写 `bot.db`、不进内存窗口、不产生候选；只处理用户主动私聊/转发。
- **新增凭据托管责任**：Secret 泄露 = 别人可以冒充该用户的 Bot。必须做到「加密落盘、不回传、不进日志、主密钥离线备份、解绑即删」。
- **覆盖范围收窄**：Bot 只能进「该用户自己是群主/管理员」的群；普通用户不能自动采集别人的群。**产品承诺要改成「手动粘贴/分享 + 私聊转发」为主，Bot 是增强项。**
- **个人信息风险仍在**：转发的仍是群内其他人的消息；需要「最小化、去标识、30 分钟窗口、用户主动触发、可删除」这套边界（§6）。
- **当前安全缺口**：私聊未校验发送者是否为 Bot 主人，任何人给该 Bot 发消息都会进入 owner 的转发队列；上线前建议补一次性 owner 校验码或首个 `user_openid` 白名单。

### 4.3 合规动作

- 隐私政策写清：AppSecret 由服务端加密托管、用途仅限建立该 Bot 连接、不用于其他目的；**自动群采集默认关闭，只处理用户主动转发**；用户可解绑并删除。
- 用户协议写清：这是信息整理辅助工具，不保证群消息完整/准确；用户需对自己转发的消息有合法处理权。
- 服务端最小化：不保存群消息正文到磁盘；转发队列 TTL 30 分钟；`DELETE /my/data` 可一键清理。
- 密钥管理：`QQBOT_SECRET_KEY` 只放服务端环境变量；`tenants.json` 与密钥分开备份；丢失主密钥只能让用户重新绑定。

> 工作量：App 绑定页 + 后端租户存储/ runner 已完成（2026-10-28）；**不要再去注册个体户**，除非未来明确要做「一个公开 Bot 覆盖大量别人的群」。

## 5. 如果走 B（个体户）：合规动作清单

### 5.1 三人书面协议（不签就是给自己埋雷）

至少写清：

- 出资（钱/设备/云资源谁出、算不算借款）；
- 分工与决策机制（重大事项谁拍板）；
- **收益分配**（比例、何时分）；
- **知识产权归属**：代码、设计、商标、**QQ 机器人账号/AppID**、域名、备案主体；
- **债务内部承担**（对外无限责任由经营者承担，内部按比例追偿）；
- **退出机制**（回购、估值、竞业）；
- 争议解决（管辖法院/仲裁）。

> 模板可从"合伙协议"起，**建议律师过一遍**。三个人几百块的事，能省掉以后几万的纠纷。

### 5.2 登记与经营范围

- 谁登记：**一人为经营者**（另外两人靠协议保护权益）；
- 经营范围建议：**信息技术咨询服务、软件开发、信息系统集成服务**等；
  - ⚠️ 若包含"互联网信息服务"，**经营性**需 ICP 许可证（你们免费提供服务，通常是**非经营性 → 备案即可**），具体以市场监管/通管局口径为准；
- 经营场所：先问清"住改商/托管地址"是否可行（§3.4）。

### 5.3 税务与年报：设日历

| 事项 | 频率 | 备注 |
| --- | --- | --- |
| 增值税申报（小规模） | 按季 | 无收入也要零申报 |
| 个人所得税（经营所得） | 按季预缴 + 年度汇算 | 同上 |
| 工商年报 | 每年 1/1–6/30 | 漏报有罚（§3.3） |
| 记账凭证 | 每月 | 可代账（约 2k–4k/年） |

### 5.4 合规文本与产品动作

- 隐私政策：**以个体户为主体**写，写清处理者、目的、范围、保留期、撤回方式；
- 用户协议：明确"信息整理辅助工具、不保证准确性"（**避免被当成正式通知渠道**）；
- 不收款、不承诺 SLA（减少消费者权益纠纷面）；
- 内容安全：只转发文本、**去标识化**（见 §6）、提供撤回/删除。

### 5.5 退出预案

- 个体户**注销**需先清税（可简易注销，但有条件）；
- QQ 开放平台账号/主体**不能注销** → 注册即长期绑定；
- 想好"项目结束怎么办"，别让一个空壳个体户年年产生年报/税务义务。

## 6. ⚠️ 比个体户更大的风险：转发"别人的消息"

> **当前 BYOB 边界**：`QQBOT_GROUP_COLLECT=0`，**不自动采集群消息、不存群聊正文**；只处理用户**主动私聊/转发**给 Bot 的单条消息。风险面比原方案小。但只要转发的仍是群内他人内容，本节仍然适用；未来若做群自动采集，必须按本节全部执行。

你们的链路是：**群里 A 发的消息 → 机器人 → 推给订阅了该群的用户 B**。

- B 是你们的用户，**A 不是**；
- A 没有同意你们把他的昵称、发言内容转给第三方；
- 这类内容属于**个人信息**（含昵称、openid、聊天内容），你们是**个人信息处理者**。

按《个人信息保护法》，处理个人信息需要**合法性基础**（同意、合同必需、法定义务、公共利益等）。"群成员同意"在现实中**几乎拿不到**——这是模式本身的合规难点。

**能做的降低风险措施（按有效性排序）**：

1. **去标识化**：推给用户的内容**不带发送者昵称/头像/openid**，只保留"某群有新消息"或"某成员"；
2. **只推结构化结果，不推原文**：例如只推"周五前交实验报告 / 截止 10-31"，不推完整聊天；
3. **群内公示 + 群主授权**：机器人进群时在群里明确告知"本群消息会被整理并推送给订阅者"，并取得**群主/管理员**书面同意（截图留证）；
4. **最小必要**：只处理订阅者本人所在的群；不建全量库；窗口 30 分钟（你们已做）；
5. **可撤回**：成员要求不转发时能立即生效（技术上可做"该成员消息不采集"开关）；
6. **不对外提供**：除了订阅者个人，绝不分发给第三方、不做数据出售；
7. **未成年人**：校园群可能含未成年人，14 岁以下属敏感个人信息，需监护人同意——**这是个真实隐患**，建议在协议里限定"仅限本校在读学生且年满 14 周岁"并做声明。

> **建议**：这一块**值得花一次律师咨询费**（尤其"群内公示 + 群主授权"能不能构成有效基础）。这不是技术能绕过去的。

## 7. 我的建议（决策树）

```
现在要做的是「一个公开 Bot 覆盖大量别人的群」吗？
│
├─ 不是（当前路线）
│    → BYOB：用户自己建 Bot，填 AppID/AppSecret；我们只托管连接
│      已落地：私聊/转发 → App 待确认；手动粘贴/分享仍是主链路
│      不做：个体户、公开 Bot、群自动采集
│      风险：凭据托管 + 转发他人消息（§4/§6）
│
└─ 是（未来要公开、要规模、要长期运营）
     → 注册个体户（先确认经营场所）
       必须同时：三人协议 + 记账报税 + 年报日历 + 统一主体 + §6 措施
       若明确要商业化/融资 → 直接有限责任公司，别用个体户
```

**我的倾向**：

- **当前阶段**：**不要注册个体户**。BYOB 已能验证「用户转发 → 待确认」的核心价值；个体户只会增加税务/年报/无限责任/不可逆账号。
- **如果未来确实要一个公开 Bot 覆盖别人的群**：那时再注册个体户；**个人主体不能升级，所以是“那时新注册”，不是现在先占坑**。
- **不管走哪条**：先把 §6 的个人信息合法性想清楚再上线。BYOB 并没有消除「转发群内他人消息」的问题。
