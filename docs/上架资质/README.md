# 上架资质办理指引（AI 文本生成）

> 适用场景：AGC 审核驳回「应用缺少 AI 文本生成的资质证明文件，不符合相关法律法规要求」。
> 本目录只放**要签字盖章的材料**；代码侧的合规改造在仓库里，见文末「代码侧现状」。

## 0. 一句话结论

这一条**不是代码问题**，是法规资质问题。应用属于 AGC 资质表里的
[「深度合成或生成式人工智能服务」](https://developer.huawei.com/consumer/cn/doc/doccenter-submission/80301)，
要交**四件**材料；审核意见只点了后两件（《安全评估报告》＋提交结果截图），但缺任何一件都会被再驳一次。

### 只被问「标识材料」（问题2）时怎么最快回

审核那次的原话是「请补充提交人工智能生成合成内容标识相关材料：**应用内已添加内容显式标识截图**」。
这一条**不用等盖章**，把 `素材/` 下两张 PNG 直接传到「分发 → 版本信息 → 版权信息」即可：

- `素材/显式标识-任务详情页（AI生成）.png`：任务详情页底部的「AI生成 · 以上内容由 AI 生成，仅供参考，请在核对后再使用」；
- `素材/显式标识-添加任务半模态（AI生成）.png`：「添加任务」流程里 AI 解析完成后出现的同一条标识。

> 两张截图取自本机模拟器实机运行，内容由应用真实调用 `/api/relay/parse` 生成（真实 AI 结果，非构造数据）。
> 想把背景换成手机上的真实界面当然更好，重截一遍即可替换同名文件。

因为本应用**支持导出 CSV / JSON**（属于「提供生成合成内容文件的导出」），50111-10 要求的是**说明函 + 隐式标识截图**这一支，
所以只交显式标识截图可能仍被追问 —— 建议与说明函一起交（说明函里还差最后一张「导出 JSON 的 AIGC 字段」截图，见 §4）。

- 报告/说明函上的**服务名称**必须与 AGC 提交的**应用名称逐字一致**（本仓库显示名是「知了 · 信息助手」，文档里先填了「知了」，以 AGC 实际名称为准）；
- **单位名称**必须与 AGC 账号**实名主体**一致；
- 平台提交截图上的**服务名称/主体名称**同理；
- 说明函需**签章**，安全评估报告需**开办主体责任人签字 + 单位盖章 + 评估负责人签字 + 评估单位盖章**（自评估时评估单位 = 本单位）。

## 1. 办理顺序（建议）

```text
① 定主体：AGC 实名主体 = 单位名称（企业填统一社会信用代码；个人主体按平台要求填证件号码）
      ↓
② 算法备案（beian.cac.gov.cn）—— 周期最长，先启动
      ↓ 拿到备案编号 + 查询结果截图
③ 安全评估：填表 → 打印 → 签字盖章 → 提交到全国互联网安全服务管理平台 → 等「审核通过」
      ↓ 拿到提交结果截图
④ 标识材料：说明函贴截图 + 盖章（可与 ②③ 并行准备）
      ↓
⑤ AGC 上传：分发 → 版本信息 → 版权信息；备注：分发 → 版本信息 → 应用审核信息 → 备注栏
      ↓
⑥ 提审新版本
```

## 2. 算法备案怎么填（针对本应用）

入口：<https://beian.cac.gov.cn/>，三步填报（主体信息 → 算法信息 → 关联产品及功能）。
本应用是**服务提供者**（自己运营 `https://distiller.ltd` 后端，由后端调用大模型产出待办内容），
不是「只做技术支持」，所以按服务提供者填报。

建议填报口径（按实际情况改）：

| 填报项 | 建议内容 |
| :-- | :-- |
| 算法名称 | 知了待办信息整理生成算法 |
| 算法类型 | 生成合成类（文本生成） |
| 应用领域 / 场景 | 校园信息整理：把群聊通知/截图/录音整理成结构化待办（标题、时间、地点、类型、标签、步骤） |
| 产品形态 | 移动应用（HarmonyOS），包名 `com.xjtu.distiller` |
| 算法自评估报告 | 按系统模板填：① 数据来源（用户主动提交的文本/图片/语音转写，不抓取全网数据）；② 生成内容范围（仅结构化待办字段，不生成自由长文）；③ 安全措施（字段白名单校验、生成结果进「待确认」由用户核对、应用内「AI生成」显式标识、导出文件 AIGC 隐式标识）；④ 风险与兜底（不提供发布/评论/群组等传播功能） |
| 拟公示内容 | 备案编号 + 公示链接（**备案通过后**才填） |

⚠️ 备案通过后有一个**代码动作**：法规要求「在对外提供服务的网站、应用程序的显著位置标明备案编号并提供公示信息链接」。
现在应用内还没有这块位置，拿到编号后告诉开发者，加在「设置 → 关于」一行（点击打开公示链接）即可。

## 3. 安全评估怎么提交

1. 打开 `安全评估信息（待盖章）.docx`，把红色【】提示逐项填掉（单位名称、机构代码、注册地、联系人、留存天数等），删掉红色提示与「说明」行；
2. 打印 → 开办主体责任人签字、单位盖章、评估负责人签字、评估单位盖章、填日期 → 扫描成 PDF；
3. 登录 [全国互联网安全服务管理平台](https://www.beian.gov.cn/portal/index.do)，按《安全评估指引》提交；
4. 等审核/现场检查出结果，**截图要能看清「服务名称」「主体名称」「审核通过/通过」字样**，名称必须与 AGC 一致。

文档里标了【待确认】的三处，请按实际情况改（不要照抄，评估材料与事实不符风险更大）：

- 第 3 项：服务端日志留存天数；
- 第 4 项：服务端/客户端是否已加敏感词或合规过滤（**若还没有，建议先加再提交这一项**）；
- 第 6 项：是否需要在应用内加「一键举报」入口。

## 4. 标识材料怎么准备

`人工智能生成合成内容标识说明函（待盖章）.docx` 已在官方模板上填好应用名称与包名，「图片/音频/视频/其他」已标注「不涉及」，
**两张显式标识实机截图也已嵌入第 2 页**（见 §「素材目录」）。还差三步：

| 步骤 | 做什么 |
| :-- | :-- |
| ① 勾选类型 | 正文里「（□文本 □图片 □音频 □视频 □虚拟场景 □其他）」手动勾选**「文本」** |
| ② 补隐式标识截图 | 见下表最后一行；贴到「文本文件元数据隐式标识截图」处，删掉那行红色【待补…】 |
| ③ 填名称盖章 | 「企业名称」填 AGC 实名主体、「日期」填提交当天，盖章（个人主体按平台要求签字） |

隐式标识那张截图怎么取（真机上做，1 分钟）：

| 截图 | 在哪一屏取 |
| :-- | :-- |
| 文本文件元数据隐式标识 | 设置 → 导出任务（JSON）→ 用文件管理器打开导出的 `.json`，截顶部 `"AIGC"` 那一行；若导出 CSV，则截同名的 `xxx.csv.aigc.json` |

操作要点：

- 贴完截图后把红色提示删掉，别把提示一起交上去；
- 隐式标识字段长这样（附录 E 格式，值是字符串）：
  `"AIGC": "{\"AIGC\":{\"Label\":\"1\",\"ContentProducer\":\"com.xjtu.distiller\",\"ProduceID\":\"…\",…}}"`

## 7. 风险与退路

- **主体门槛**：算法备案与安全评估都要真实可核验的主体信息，安全评估还需单位盖章与现场检查。个人开发者常常卡在这一步——如果备案系统不接受当前主体，四件材料就凑不齐。
- **退路**（审核意见第 2 条给的）：把云端 AI 文本生成下线（后端不再返回模型生成的待办内容），在「应用审核信息 → 备注栏」说明「应用内已无 AI 文本生成模块」，同时清掉应用内「AI生成」标识与宣传口径。代码改动量与影响面已评估过，随时可以走这条。
