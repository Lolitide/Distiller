## 2. 权威源在哪

- `开发指南.md` 与 `99-附录-取证台账.md` 的**权威副本在 `E:\Program_File\HMOS_proj\Distiller-DOC\`**（课程交付目录）。本目录下的是同步过来的副本：开头有一行 `<!-- 本文件是镜像副本…… -->` 的就是。
- **改动请改源文件，然后运行 `tools\sync-docs.ps1` 回灌**；直接改副本会在下次同步时被覆盖。
  ```text
  powershell -File tools\sync-docs.ps1           # 演练，只报告不写
  powershell -File tools\sync-docs.ps1 -Apply    # 真写
  ```
  脚本会顺手把正文里裸写的 `99-附录-取证台账.md` 改写成 `docs/99-附录-取证台账.md`（仓库里它是子文件），这个改写是幂等的。
- 三条 `_调查/` 笔记两边内容相同，副本存在仓库里是为了让引用能就地打开。
- `第一天开发文档.md` 与 `第一周开发指南.md` **没有镜像声明，它们只在仓库里**。这两份是随开工写出来的执行文档，不是课程交付材料：往后每周照着开发指南 §7.4 的模板继续往下写就行，不必回灌到 `Distiller-DOC\`。

## 5. 本节最重要的一句话

**这份指南的价值不在「写了什么」，而在「每条结论都能追到出处，追不到的地方明写了未取证」——所以任何一条你觉得不对的结论，先去台账里找它的来源，再决定要不要改。**
