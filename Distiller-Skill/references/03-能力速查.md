## 1. 解析链路 · Natural Language Kit（实体抽取）

| 硬约束 | 值 |
| :-- | :-- |
| 文本长度 | **不超过 1000 字符**，超了必须自己切片 |
| 实体类别 | `EntityType` 只有 **10 类**：DATETIME / EMAIL / EXPRESS_NO / FLIGHT_NO / LOCATION / NAME / PHONE_NO / URL / VERIFICATION_CODE / ID_NO —— **没有「事项 / 作业 / 考试」这类实体** |
| 模拟器 | **不支持**（原文「该能力当前不支持模拟器。」） |
| 支持语言 | 简体中文、英文、繁体中文 |
| 时间实体的 `jsonObject` | 键为 `time`，值为数组；**周期用 `repeat`，不要用 `rrule`**（原文「不一定准确，具体以 repeat 为准（参考数据，不建议使用）」） |
| `start` 的取值形状 | `2021-08-28T08:00:00`（日期+精确时间）/ `2021-08-28TM`（日期+模糊时间）/ `2021-08-28`（日期）/ `T08:00:00`（周期时间）/ `TM`（周期时间） |
| `isIllegal` | 原文给出四类会被判非法的例子（「2月30号」「每周上午8点」缺周几、「每月周一8点」缺几号、「每年8号上午9点」缺几月） |
| `EntityConfig.timestamp` | 标注 `@since 26.0.0` —— **目标 6.0.2(22) 上不可用**，不要写进代码 |

**结论**：平台只出「时间 + 地点 + 电话号码」等实体；**「事项提取」是自研规则，不是平台能力**。
长群消息必须**先切片再抽取**（按 1000 字符），并且抽取逻辑**必须真机联调**（模拟器验证不了）。

## 5. 提醒 · 代理提醒（Background Tasks Kit）+ 日历兜底（Calendar Kit）

### 5.1 代理提醒

| 硬约束 | 值 |
| :-- | :-- |
| 准入 | **手机/平板/PC 受管控，应用无法直接使用**；智慧屏、穿戴无此限制。要走两条路之一：① 改日历 ② 向华为申请开放能力（AGC → 项目设置 → 开放能力管理 → 代理提醒），**反馈期 8 个工作日** |
| 申请通过后 | **调试与发布都必须重新生成 Profile 并改用手动签名** |
| 条数上限 | 单个普通应用**有效/未过期提醒不超过 30 条**（全设备总和 ≤ 12000）；超了报 **`1700002`**。**点 CLOSE 才算过期**，周期性提醒永远算有效 |
| 跳转 | 点击提醒跳转的应用必须是申请能力的**本应用** |
| 模拟器 | **支持**（自 API 20 起） |
| 通知依赖 | 代理提醒到点后用 **Notification Kit 发通知** → **通知授权是前置条件** |
| 去重 | `notificationId` 相同的提醒会**互相覆盖** → 必须与任务 id 建立确定性映射 |

**注意**：代理提醒的开放能力**尚未申请**，而团队全班底只有**一台** 6.0.2(22) 真机（验证机）→ 一旦要验，**必须排队串行**。
「获批后那台手机是否还受管控」**未验证**（见 `06-未取证清单.md`）。你自己的机器上有没有连设备，用 `devecocli device list` 现查。
