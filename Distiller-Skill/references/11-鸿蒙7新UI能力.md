## 1. 沉浸光感（系统材质 + 空间动效）· `@since 26.0.0`

**是什么**：ArkUI 提供的一套高品质视觉与动效体系，由两部分组成 ——
**沉浸式系统材质**（`ImmersiveMaterial`，通过 `systemMaterial` 接口设置，自动影响组件的背景色、边框颜色、边框宽度、阴影和材质滤镜 `materialFilter`）
与**空间动效**（组件弹出时的形变、流光）。会按设备算力档位与用户在系统设置里的强弱自适应。

**五种材质样式 `ImmersiveStyle`**（从薄到厚）：`ULTRA_THIN`（浮动工具栏）/ `THIN`（搜索框）/ `REGULAR`（通用）/ `THICK`（菜单）/ `ULTRA_THICK`（弹窗）。

**`ImmersiveOptions` 可配项**：`materialColor`、`colorInvert`、`applyShadow`、`interactive`（按压弹性形变）、`lightEffect`（光感交互反馈）。

**应用级 vs 组件级**：可通过 `module.json5` 做应用级开启（`MaterialState` 的 DEFAULT / ENABLE / DISABLE 对应三个 value 枚举值），
也可在组件上单独设置；`uiMaterial.getMaterialInfo()` 可读当前状态；`uiMaterial.Material.empty` 可单独关掉某个组件的材质。

**服务端组件清单**（官方列举）：弹出框 Dialog、Toast、AlphabetIndexer、ChipGroup、Chip、Select、菜单控制、Toggle、SegmentButton、SegmentButtonV2、Slider、bindSheet、SelectionMenu、Text（设置 `copyOption` 后的文本菜单）。

## 2. 容器断点 `ContainerReader` · `@since 26.0.0`

**是什么**：**按容器自身尺寸**取断点做响应式布局的组件，不再依赖窗口尺寸。通过双向绑定实时返回容器的尺寸与断点，
使**同一页面里的多个容器可以各自拥有独立的断点状态**。

**硬约束**（官方原文要点）：
- `ContainerReader` **父组件不要依赖其子组件确定自身尺寸**；
- 组件尺寸需要由父容器和自身布局确定，**不受子组件影响**。父容器是 `Flex` / `Column` / `Row` 时撑满剩余空间；其它父容器时撑满父容器；
- 接口参数**必须使用状态变量结合双向绑定（`!!` 语法）**，否则后端算出尺寸变化时前端不会刷新；
- 卡片能力与元服务能力均自 API 26.0.0 起支持；仅在 Stage 模型下可用。

**对本项目的价值**：手机单端也要适配 360vp 宽度不出现横向滚动（`01-项目基线.md` 的目标），
`ContainerReader` 让「一页里不同区块各自的宽度档位」可表达，比只看窗口断点更精确 —— 但**本项目目前 `deviceTypes` 只有 `phone`**，
先评估是否值得引入，别为单端过度设计。

> [!warning] 该项目能力与本项目的 V2 规矩有冲突，用之前必须留意
> 官方 ContainerReader 的**全部示例都用 V1 的 `@State`**，指南里甚至写着「必须是 `@State` 修饰的状态变量」。
> 而本项目一律 V2（`@Local`/`@Param`）。把 `@Local` 用在 `ContainerReader` 的 `!!` 双向绑定上是**推断**，
> 不是官方明文 —— 已记进 `06-未取证清单.md`。抄 `templates/container-reader.ets` 时注意它每个绑定行都标了这个推断。
> 另：`WidthBreakpoint` / `HeightBreakpoint` 在官方示例里**未 import 直接使用**，推断为 ArkUI 全局枚举，同样未取证。

## 4. 自定义组件全局复用池 · `@since 26.0.0`

**是什么**：可针对指定的 `@Reusable` / `@ReusableV2` 复用组件**配置复用池**，提供**全局复用**能力
（相对于默认的、按组件节点局部的复用）。官方指南标题即「全局复用：集中化的组件回收与复用」。

**对本项目的注意点**：本项目新代码用**状态管理 V2**，所以只能使用 **`@ReusableV2`**。
官方明确区分 V1 的 `@Reusable` 与 V2 的 `@ReusableV2`；混用矩阵里有一条实际结论 ——
**V2 普通组件当父 + V1 复用组件当子 = 「不支持，编译告警，实际使用子组件不创建」**，这是功能性故障而不是风格问题。
V2 下 `aboutToReuse` **无入参**（与 V1 的硬差异）。详见 `02-编码规约.md`。

**未取证**：「**全局复用池 + List/Repeat**」这个组合**没有任何官方文档演示过** ——
全局池的示例全用 `if` 切换子组件，而 List/WaterFlow + `@ReusableV2` 的示例不配全局池。
`templates/global-reuse-pool.ets` 是把两个半边拼起来的，**26.0.0 上必须实测滑动时回调是否真打到全局池**。

## 7. UX 行为变更（**只有把 targetSdkVersion 提到 26 才会生效**）

| 变更 | 变更前 → 变更后 | 影响面 |
| :-- | :-- | :-- |
| **表单类组件触摸热区最小高度** | **28vp → 32vp** | `Button`、样式为 Button 的 `Toggle`、`Select`、`Chip`、`ChipGroup`。官方给的恢复写法是 `.responseRegion(undefined)`（恢复为与组件实际大小一致）；若自定义了高度或热区，随自定义大小生效 |
| **内置文本的组件文本样式优化** | 默认优化三类问题：孤字换行、小语种（藏语/缅甸语）行高异常截断、按单词换行导致单词截断 | 所有内置文本的 ArkUI 组件 → **可能出现界面排版变动**，需按实际情况调整 |
| **notofonts 三方件小语种字体升级** | 修复蒙古语/天城体/缅甸语显示；**部分数学符号（`NotoSansMath-Regular.ttf`）显示变大** | 可能出现排版变动（起始 API Level 11，不是 26 独有，但列在同一份 UX 变更里） |

> **这是「要不要提 targetSdkVersion」的核心权衡**：热区从 28vp 变 32vp 会改变**所有**表单控件的默认尺寸，
> 360vp 宽度下的紧凑布局首当其冲。**在决定提版本之前，先找一台 26.x 的设备（模拟器或真机，用 `devecocli emulator list` / `devecocli device list` 看手上有什么）做一次全页面走查。**
