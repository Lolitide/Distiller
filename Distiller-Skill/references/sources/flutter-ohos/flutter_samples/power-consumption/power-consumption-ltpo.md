# LTPO 降负载方案

在 OpenHarmony 系统中，屏幕刷新率多档策略。Flutter 中的 LTPO 方案主要适用于"智能"刷新模式：当用户处于静止、空闲或低交互状态时，系统优先维持较低的刷新频率；当发生滚动、动画、抛滑等交互动作时，应用可按当前速度与场景动态提升帧率，以兼顾流畅度和功耗。

---

## 功耗测试工具

为验证 LTPO 降负载效果，建议结合以下工具和方法进行测试：

### 1. 系统显示设置

打开"设置" > "显示和亮度" > "屏幕刷新率"，将屏幕刷新率切换为"智能"。


### 2. 开发者选项中的刷新频率显示

打开"设置" > "系统" > "开发者选项"，开启"显示刷新频率"。

启用后，屏幕左上角会显示两个数字：

- 左侧数字：目标帧率档位（期望帧率）；
- 右侧数字：实时帧率。

开发者可以通过观察左侧数字快速判断 LTPO 当前是否按预期在降低或提升刷新率。

### 3. 功耗观测建议

结合以下方式评估功耗收益：

- 比较静止页面与滚动页面在智能刷新模式下的帧率分布；
- 对比 "高刷新率" 与 "智能刷新率" 下的系统功耗与发热；
- 检查列表抛滑、轮播、Tab 切换等页面在空闲后是否快速回落到 60fps；
- 验证动画与交互在用户操作期间是否依旧保持高帧率反馈。

## 使用场景

LTPO 降负载方案适用于需要兼顾流畅性和低功耗的典型场景，尤其适用于以下页面和交互方式：

| 场景 | 适配价值 | 典型表现 |
| --- | --- | --- |
| 自定义平移动画 | 动画仍保持流畅，同时空闲后降低到低功耗帧率 | 滑动中可达 90fps/120fps，停止后回落至 60fps |
| 转场平移动画 | 页面切换时有足够帧率保障，静态停留时降低功耗 | 页面切换时保持流畅，后台/空闲切回低帧率 |
| 滚动列表抛滑 | 抛滑过程中实时提高帧率，手指离开后快速回落 | 120fps → 90fps → 60fps 按速度衰减 |

适用的典型时机包括：

- 页面在后台或非活动状态下，动画不应继续消耗高刷资源；
- 用户与页面交互结束后，系统应尽快降回合理的低功耗帧率；
- 长时间静态显示区域不需要维持高刷新频率。

### 适配依赖

#### DevEco Studio

使用 LTPO 功能前，建议升级至支持 API 20 的版本，确保编译与运行环境能够获取最新的显示同步能力和系统接口支持。

#### flutter_flutter

LTPO 功能依赖 Flutter SDK 代码仓中的版本适配能力，建议使用支持 LTPO 的 Flutter 分支，确保动态帧率能力和平台适配逻辑已集成。Flutter 升级请参照[升级文档](../version/flutter-oh-upgrade-guide.md)。

### 详情

#### LTPO 降负载原理

LTPO 降负载方案的核心思想是"以需求驱动刷新"：

- 当页面处于稳定视图时，降低到更低帧率档位；
- 当页面发生滚动、拖拽、动画、抛滑等交互动作时，提升目标帧率；
- 当交互结束后，尽快回落到 60fps 或更低。

这使 Flutter 在 OpenHarmony 平台能够保持较低的平均功耗，同时不牺牲交互时的响应感和视觉一致性。

通常情况下，LTPO 是通过"速度投票"方式决定动画与滚动感知的目标帧率。速度越高，说明页面内容在快速移动，用户更关心动作连续性，因此拉高帧率；速度越低则说明页面更接近静止状态，帧率可下降以减少无意义渲染。

#### Flutter 中的实现方式

在 Flutter 中，LTPO 涉及三类关键行为：

1. 刷新率感知：应用或系统可感知当前屏幕刷新率模式；
2. 帧率投票：动画和滚动事件根据速度选择合适的目标帧率档位；
3. VSync 协调：通过与平台显示同步机制协同，将目标帧率与实际显示刷新对齐。

这部分逻辑位于 Flutter 运行时和 OpenHarmony 适配层，其中 `VsyncWaiterOHOS`、`NativeVsyncChannel` 和 LTPO 开关检查等能力是核心点。开发者通常不需要直接修改这些底层实现，但必须确认使用的 Flutter SDK 已包含该能力。

#### LTPO 配置文件说明

LTPO 的核心配置文件为 `framesconfig.json`，它存放在 ArkUI 应用工程中 Flutter 模块的 `src/main/resources/rawfile` 目录下，位置与 `flutter_assets` 同级。

开发者适配此功能，不强制依赖配置文件，默认开启，升级到对应版本即可使用。若需关闭此功能，开发者可以添加配置文件，修改 `SWITCH` 配置项为 `0`，即可关闭。

配置项包括：

| 子项 | 描述 | 类型 |
| --- | --- | --- |
| SWITCH | 动态帧率开关，0 表示关闭，1 表示开启 | 整型 |
| TRANSLATE | 平移动画的帧率映射表 | 数组 |
| SCALE | 缩放动画的帧率映射表 | 数组 |
| ROTATION | 旋转动画的帧率映射表 | 数组 |

当前默认帧率映射表：

| 序号 | 最低滑动速度 | 最高滑动速度 | 帧率 |
| --- | --- | --- | --- |
| 1 | 800 | 无限大 | 90 |
| 2 | 77 | 800 | 120 |
| 3 | 46 | 77 | 90 |
| 4 | 10 | 46 | 72 |
| 5 | 0 | 10 | 60 |

> **注意**：最终屏幕实际帧率仍由系统决策，不完全由配置表直接固定。

示例结构：

```json
{
  "SWITCH": 1,
  "TRANSLATE": [
    { "serial_number": 1, "min": 800, "max": -1, "preferred_fps": 90 },
    { "serial_number": 2, "min": 77, "max": 800, "preferred_fps": 120 },
    { "serial_number": 3, "min": 46, "max": 77, "preferred_fps": 90 },
    { "serial_number": 4, "min": 10, "max": 46, "preferred_fps": 72 },
    { "serial_number": 5, "min": 0, "max": 10, "preferred_fps": 60 }
  ]
}
```

如果应用工程是新建工程，通常模板中已携带此文件；如果工程已存在且需要自定义配置，则需要手动复制到：

    ohos/entry/src/main/resources/rawfile/framesconfig.json

#### 功耗测试工具与观察方式

为了评估实际功耗收益，建议在设备上完成以下检查：

- 打开"智能"刷新；
- 开启"显示刷新频率"；
- 在滚动列表页面进行抛滑；
- 观察帧率从 `120fps` 逐步降低，最终在停滞后落到 `60fps`；
- 对比相同页面在"高刷新率模式"和"智能模式"下的发热、耗电和体验差异。

这类验证既能确认 LTPO 是否生效，也能确认其是否在合适的时机降低了负载。

#### 适配流程

1. 更新 DevEco Studio 至支持 API 20 的版本，确保所需系统能力齐全。
2. 下载适配了 LTPO 功能的 `flutter_flutter` 代码仓，并设置到环境变量中。
3. 在命令行执行 `flutter doctor -v`，确认当前 Flutter 路径与分支均为包含 LTPO 的版本。
4. 如需自定义配置，在应用工程中确认 `framesconfig.json` 文件存在且位于 `ohos/entry/src/main/resources/rawfile` 路径下。
5. 检查 `SWITCH` 是否为 `1`，如果不是则修改为 `1`。
6. 在设备中打开"设置" > "显示和亮度" > "屏幕刷新率"，并切换到"智能"。
7. 在应用中打开带有滚动、动画或翻页逻辑的页面，验证帧率能够随交互状态变化。

#### 验证流程

1. 检查设备系统版本是否满足 LTPO 运行要求。
2. 确认设备已具备相应显示能力和策略控制权限；如没有，需联系平台/接口人同步系统版本与策略配置。
3. 打开"智能"刷新，并确认页面处于交互状态时有高帧率反馈。
4. 在页面抛滑或滚动时，观察左侧显示的目标帧率档位是否从较高值逐步回落。
5. 停止操作后，观察系统是否在 3 秒左右或更短时间内回落到 60fps。
6. 对比不同页面在高刷新和智能刷新中的体验、发热和功耗表现。

## 总结

Flutter 的 LTPO 降负载方案，是在 OpenHarmony 智能刷新能力与 Flutter 动画/滚动速度感知之间建立一层协同机制。它解决的核心问题不是"是否需要更高刷新率"，而是"哪些时段值得持续高刷，哪些时段应该及时回落低刷"。

这套方案对以下几类应用最具意义：

- 长时间静态展示型页面；
- 频繁滚动列表；
- 动画较多的应用首页和转场页；
- 需要在可靠体验与低功耗之间取得平衡的场景。

如果开发者正确接入 LTPO，并结合合理的页面生命周期控制和动画策略，就可以在保持交互流畅度的同时，显著降低无意义刷新带来的功耗占用。
