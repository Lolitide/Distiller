# Using FlutterPage

This document describes how to embed Flutter rendering content into a native ArkUI page through `FlutterPage`. `FlutterPage` is an ArkTS component provided by `flutter_ohos`. In the standalone Flutter app mode, it works with `FlutterAbility` (the app entry responsible for creating and managing the Flutter engine) to present Flutter content in a host page, and it supports overlaying native ArkUI components on top of the Flutter content.

---

## Core Concepts

| Term | Description |
|------|------|
| `FlutterPage` | ArkTS UI component that takes a `viewId` parameter and renders Flutter content in a native page |
| `viewId` | Unique identifier of the `FlutterView`; generated by `FlutterAbility` when it creates the engine, and injected into the host page through `LocalStorage` |
| `FlutterView` | Rendering view object created internally by `FlutterAbility`; `FlutterPage` binds to it by `viewId` |
| `FlutterAbility` | Ability-level entry of a standalone Flutter app; extends `UIAbility` and internally handles engine creation, `viewId` injection, and lifecycle management; plugin registration is done by overriding `configureFlutterEngine` |

## Implementation Steps

### Step 1: Create a Page to Host FlutterPage

There are two scenarios for the page that hosts `FlutterPage`: directly reusing the default project home page `pages/Index`, or creating a new Page as the host. Both must have their path registered in `main_pages.json`; the difference is whether a new file is created and whether `pagePath()` needs to be overridden.

#### Scenario 1: Using the default home page `pages/Index`

When the project is created, `pages/Index.ets` is generated by default and its path is already registered in `main_pages.json`. Therefore, there is no need to create a new file or override `pagePath()` — just use `FlutterPage` directly in `pages/Index.ets` (see Step 3).

1. Confirm that the default home page is registered in `ohos/entry/src/main/resources/base/profile/main_pages.json`:

   ```
   {
     "src": [
       "pages/Index"
     ]
   }
   ```

#### Scenario 2: Creating a new Page as the host

To host `FlutterPage` on a newly created page, you need to create the file, register the path, and override `pagePath()` in `EntryAbility` to point to the new page.

1. Right-click the `ohos/entry/src/main/ets/pages` directory and choose **New** → **Page** → **Empty Page** to create a Page (for example, `pages/NewIndex`).

2. Register the new Page in `main_pages.json`:

   ```
   {
     "src": [
       "pages/Index",
       "pages/NewIndex"   // Register the new Page
     ]
   }
   ```

3. Override `pagePath()` in `EntryAbility` to return the new page path:

   ```ts
   export default class EntryAbility extends FlutterAbility {
     pagePath(): string {
       return 'pages/NewIndex';
     }
   }
   ```

### Step 2: Configure EntryAbility

```ts
import { FlutterAbility, FlutterEngine } from '@ohos/flutter_ohos';
import { GeneratedPluginRegistrant } from '../plugins/GeneratedPluginRegistrant';

export default class EntryAbility extends FlutterAbility {
  configureFlutterEngine(flutterEngine: FlutterEngine): void {
    super.configureFlutterEngine(flutterEngine);
    // Plugins must be registered; omitting this causes MissingPluginException
    GeneratedPluginRegistrant.registerWith(flutterEngine);
  }
}
```

> `GeneratedPluginRegistrant` is generated automatically by `flutter build har` into `entry/src/main/ets/plugins/` (the file is listed in `.gitignore` and not committed to the repository); it appears once the build is complete, so there is no need to write it manually. `FlutterAbility` creates the engine and writes the `viewId` into the page's `LocalStorage`.

### Step 3: Use FlutterPage in the Page

```ts
import { FlutterPage } from '@ohos/flutter_ohos';

let storage = LocalStorage.getShared();

@Entry(storage)
@Component
struct Index {
  @LocalStorageLink('viewId') viewId: string = '';

  build() {
    Stack({ alignContent: Alignment.Top }) {
      FlutterPage({ viewId: this.viewId })
      Text('Components overlaid above FlutterPage').margin(30)
    }
  }
}
```

> `@Entry(storage)` and `@LocalStorageLink('viewId')` are used to receive the `viewId` injected by `FlutterAbility`; `FlutterPage` renders the Flutter content based on this id.

## Overlaying Native Components on Top of FlutterPage

`FlutterPage` is essentially a rendering surface and can be placed in a `Stack` like a regular ArkUI component. With the stacking behavior of `Stack`, native components declared after `FlutterPage` are rendered on top of the Flutter content:

```ts
Stack({ alignContent: Alignment.Top }) {
  // Bottom layer: Flutter rendering content
  FlutterPage({ viewId: this.viewId })
  // Top layer: native ArkUI components
  Text('Components overlaid above FlutterPage').margin(30)
}
```

Common overlay scenarios include a native top navigation bar, floating buttons, loading dialogs, and debug overlays. Events on the overlaid components are still handled on the native side and do not pass through to Flutter.

## Building and Running

### Configuring Signing

Open the ohos project in DevEco Studio, choose **File → Project Structure → Project → SigningConfigs**, select **Automatically generate signature**, and complete signing.

### Building and Packaging

Run the following command in the project root directory:

```sh
flutter build hap --debug
```

### Running

After connecting an OHOS device, run:

```sh
flutter run -d <device-id>
```

You can also run the entry module directly in DevEco Studio.
