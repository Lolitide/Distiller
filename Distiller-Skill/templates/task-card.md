# 任务卡（Task Card）

七个槽位固定：**目标 / 交付物 / 依赖 / 验收标准 / 风险 / 归属 / 预估**。
验收标准必须是复选框列表 —— 它决定这张卡能不能被判定为「完成」，写成叙述句就无法勾选。
拷贝下面「空白任务卡」使用；不要改动槽位名称。

---

## 填写规则（每张卡都要遵守）

1. **目标**只回答「为什么」。出现「用 XX 实现」这类字样说明写错槽位了，那是交付物。
2. **交付物**必须是路径。没有路径的交付物（例如「一个更好的架构」）要拆到有路径为止。
3. **依赖**分三类写全：前置任务、外部条件、环境。环境缺设备时要在开卡时就写明，不要等卡在验收时才发现。
4. **验收标准**三条硬性要求：
   - 每条都能被第三个人在十分钟内判定通过与否；
   - 至少一条是「跑起来看结果」而不是「看代码」；
   - 涉及 26.0.0 能力时，必须有一条明确的 `未验证` 或 `需真机验证` 条目，不许默认它成立。
5. **风险**写「触发条件」，不写「可能会出问题」。没有触发条件的风险不是风险，是担忧。
6. **归属**的写入范围是硬约束：同一时间两份卡的写入范围不得重叠。
7. **预估**给区间无意义，给数字；关键路径上的卡要额外标出。

## 示例任务卡（EXAMPLE —— 仅作填写示范，不是待办）

> 下面这张卡是**填好的样例**，用来演示七个槽位各自的粒度。
> 它是 `W1-T03`，属于知了 / Distiller（`com.xjtu.distiller`）第一周的工作。

```markdown
### 任务卡 W1-T03 · 六页静态原型

**目标**
> 在写任何业务逻辑之前，先把知了的六个主界面用真实 ArkUI 组件堆出来，确认信息层级、
> 断点行为和跳转关系在 6.0.2(22) 手机上成立。目的是让后续 ViewModel 开发有确定的
> 落点，避免「先写逻辑再改 UI」造成的返工。

**交付物**
- `entry/src/main/ets/pages/BookshelfPage.ets` —— 书架（首页）
- `entry/src/main/ets/pages/ImportPage.ets` —— 导入
- `entry/src/main/ets/pages/ReaderPage.ets` —— 阅读
- `entry/src/main/ets/pages/DistillPage.ets` —— 蒸馏结果（卡片流）
- `entry/src/main/ets/pages/CardDetailPage.ets` —— 卡片详情
- `entry/src/main/ets/pages/SettingsPage.ets` —— 设置
- `entry/src/main/resources/base/profile/main_pages.json` —— 六页路由注册
- 六页均为静态数据，不含任何 service 调用

**依赖**
- 前置任务：`W1-T01`（设计 token 与栅格基线）；`W1-T02`（Navigation 骨架与路由表）
- 外部条件：`W1-T01` 提供 `entry/src/main/ets/common/Tokens.ets`
- 环境：一台 6.0.2(22) 真机（已具备）；**不需要**模拟器

**验收标准**
- [ ] `devecocli build` 通过，产物落在 `entry/build/default/outputs/default/`
- [ ] 六页全部使用 ArkUI 状态管理 V2 装饰器，`entry/src/main/ets/pages/` 下 grep 不到
      `@State` / `@Prop` / `@Link` / `@Observed` / `@Provide` / `@Consume` / `@Watch`
- [ ] 页面中不出现任何系统能力调用（`@kit.*` 的 import 只允许出现在 `service/` 与 `common/`）
- [ ] 六页两两之间均可通过 Navigation 到达并返回，返回栈正确
- [ ] 在 6.0.2(22) 真机上逐页截图，六张图的文字无截断、无溢出、无遮挡
- [ ] `oh-package.json5` 的 `dependencies` 仍为空对象
- [ ] 未使用任何 26.0.0 才有的 API；若使用了，该处必须带 `// 未取证：26.0.0 能力，本机未验证`
      且当页在真机上不崩溃

**风险**
| 风险 | 触发条件 | 影响 | 对策 |
| :-- | :-- | :-- | :-- |
| token 未定稿导致六页返工 | `W1-T01` 晚于本卡开工仍未交付 Tokens.ets | 六页样式集体重写 | 先用硬编码色值实现，全部集中在 `Tokens.ets` 的本地副本里，T01 交付后整文件替换 |
| 卡片流页在长列表下掉帧 | 蒸馏结果页用 `Column` 直铺 50+ 卡片 | 首屏卡顿，后续要重写 | 该页直接使用 `List` + `Repeat`，从一开始就按列表结构写 |
| 误用 V1 装饰器 | 参考了官方文档中 V1 示例（ContainerReader / uiMaterial 的官方样例均为 V1） | 编译告警与状态不同步 | 参照任何官方样例时，`@State`→`@Local`、`@Prop`→`@Param` 逐处替换，并以验收标准第 2 条兜底 |
| 26.0.0 组件在本机不可用 | 有人把 ContainerReader / 系统材质写进原型 | 页面在真机上异常 | 本卡禁用 26.0.0 能力，另开卡 `W2-T07` 单独验证 |

**归属**
- 负责人：`ui-prototype`
- 复核人：`lead`
- 写入范围：`entry/src/main/ets/pages/`、`entry/src/main/resources/base/profile/main_pages.json`

**预估**
- 工作量：6 人时（每页 1 人时）
- 关键路径：是（`W2-*` 全部阻塞在本卡）
- 截止：第 1 周周五
```

## 反例（这些写法会让卡作废）

| 槽位 | 错误写法 | 为什么不行 |
| :-- | :-- | :-- |
| 目标 | 「用 List 实现书架页」 | 这是交付物，不是目标；读不出「为什么」 |
| 交付物 | 「一个好看的书架页」 | 没有路径，无法判定是否交付 |
| 依赖 | 「等设计」 | 没说是哪张卡、哪份文件、缺了会怎样 |
| 验收标准 | 「页面正常显示」 | 无法机械判定，十个人有十种「正常」 |
| 验收标准 | 「代码质量良好」 | 不可判定，且无法勾选 |
| 风险 | 「可能会延期」 | 没有触发条件，等于没写 |
| 归属 | 「大家一起」 | 没有唯一负责人，出问题无人兜底 |
| 预估 | 「大概两三天吧」 | 数字缺失；且未标是否在关键路径 |
